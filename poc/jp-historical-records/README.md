# jp-historical-records

気象庁が「前後のデータが均質でない」と印を付けた官署の年を、年平均気温だけを使ったスコアで、どれだけの手間で拾い直せるかを測る。

新しい不均質を見つけるための PoC ではない。既に印が付いているものを、人が何件見直せば拾えるかを数える。候補の一覧と、この問いを選んだ理由は [survey.md](survey.md) にある。

## 問い

- 正解表: 気象庁「過去の気象データ検索」の、官署ごとの年ごとの値の表で、日平均気温の欄に引かれた赤線。赤実線と赤点線の2層がある。
- 対照の母集団: 年平均気温の値か印がある (官署, 年) の全部。標本は引かない。
- スコア: 相対均質性の検定統計量 (SNHT) を、前後8年の窓の中央で1回だけ評価したもの。
- 読み方: しきい値ごとに、Recall (印のある年のうち拾えた割合) と Inspection Load (全体のうち人が見直すことになる割合) を並べる。

## スコア

[score.py](score.py) に固定してある。実データを取る前に書き、取った後は変えていない。

候補の官署 $i$ と年 $k$ について、窓 $W_k = \{k-8, \dots, k+7\}$ を取る。

$$
q_t = T_{i,t} - \operatorname{median}_{j \in R_i} \left( T_{j,t} - \bar{T}_{j,W_k} \right), \qquad
z_t = \frac{q_t - \bar{q}}{s_q}
$$

$$
S_i(k) = n_1 \bar{z}_1^2 + n_2 \bar{z}_2^2, \qquad
\text{score}_i(y) = \max\{ S_i(y),\ S_i(y+1) \}
$$

- $R_i$ は、年々の差分どうしの相関が高い上位 10 官署。差分で選ぶのは、どちらかの系列に段差があっても選び方が引きずられないためである (Peterson & Easterling 1994)。
- $\bar{z}_1, \bar{z}_2$ は窓の前半と後半の平均、$n_1, n_2$ はそれぞれの有効な年数。統計量の形は Alexandersson (1986) の SNHT である。SNHT は分割点を動かして最大を取るが、ここでは年ごとの値が欲しいので分割点を窓の中央に固定した。
- 窓を前後8年にしたのは、気象庁の移転補正が「移転が行われた年を中心とした前後8年間」を使うためである (大野ほか 2011、気象庁の解説ページによる)。
- 年 $y$ のスコアに $S(y)$ と $S(y+1)$ の大きいほうを取るのは、年の途中で移転すると、その年の値が新旧の混合になるためである。
- どちらかの半分に有効な年が 6 未満、または窓の全年がそろう参照官署が 3 未満なら、スコアは無い。スコアが無い年は「しきい値を超えた」に数えない。

しきい値は、均質な白色雑音に同じ統計量をかけたときの 90%、95%、99%、99.9% 点である (`score.null_quantiles`、乱数の種は固定)。SNHT の臨界値表 (Khaliq & Ouarda 2007) と同じ作り方だが、統計量が違うので表の値は使えず、自分で求めた。実データでは調整していない。

## 動かし方

```sh
uv run pytest                 # 合成データのテスト
uv run python fetch.py        # 全官署の年ごとの表を取り、data/ に TSV を書く (1 秒に 1 回)
uv run python evaluate.py     # スコアをかけ、表を出す
```

実データを読む `fetch.py` と `evaluate.py` は、メモリと CPU の上限を掛けて流す。

## ファイル

| ファイル | 中身 |
|----------|------|
| `data/station_years.tsv` | 母集団の全数。官署、年、年平均気温、印 |
| `data/ground_truth.tsv` | 印のある行だけ |
| `data/scores.tsv` | 全行のスコア |
| `data/results.tsv` | しきい値ごとの集計 |
| `cache/` | 取得した HTML。リポジトリには入れない |

印は「その年と前の年のあいだの赤線」として読む。行の上の線はその年に、行の下の線は次の年に付ける。表の様式は `stats/data/css/kako.css` で確かめた。水準 1 が点線、水準 2〜4 が実線である。凡例が説明するのは実線と点線の違いだけで、水準 2〜4 の違いは書かれていないため、まとめて実線と読んでいる。

値に `]` (資料不足値) が付く年は欠測として扱う。`)` (準正常値) は値として使う。

### 分かったこと

- 点線の印 82 件のうち、いちばん厳しいしきい値で 38 件、いちばん緩いしきい値で 53 件が拾えた。そのとき人が見直す (官署, 年) は、全体の 5.8% と 34.8% である。
- 白色雑音の 90% 点をしきい値にしても、全体の 34.8% が超える。雑音だけなら 10% のはずなので、このしきい値は実データの「均質」を表していない。印の無い年のスコアが高い理由は、この PoC では分けられない (下の「分からないこと」)。
- 印のある年でスコアが無かった 14 件のうち、11 件は 1890〜1920 年代で、窓の全年がそろう参照官署が 3 未満だった。残りの 3 件は記録の端 (釧路 1889、宿毛 2025、阿蘇山 2018) で、窓が取れない。参照官署を相関だけで選び、その時代に記録があるかを見ていないことが原因で、スコアの設計の弱さである。直していない。
- スコアがあるのに 3.33 に届かなかった点線の印は 17 件ある (大阪 1933 と 1968、金沢 1991、釧路 2000、飯田 2002 など)。年平均の差に段差が出ていない。

### 分からないこと

- 印の無い年でスコアが高いもの (しきい値 8.73 で 930 件) が、誤検出か、記録されていない変化かは分からない。1 つの段差は前後の年のスコアも押し上げるので、930 件は 930 か所ではない。参照官署の側の段差も、候補の側のスコアを押し上げる。どれがどれだけ効いているかは測っていない。
- 実線の印は 3 件しか無く、うち 2 件は記録の端でスコアが無い。実線の層については何も言えない。
- 印がどの出来事 (移転、測器の変更、観測間隔の変更) に対応するかは、この表からは分からない。

### 測っていないこと

- 月別値、日最高・日最低気温の平均、ほかの要素。
- 参照官署の選び方や窓の長さを変えた場合。
- 気象庁が補正を公表している移転 (解説ページが挙げる東京など) と、ここでの印の対応。
- 官署の履歴ファイル (地点情報履歴) との突き合わせ。

### 手順の記録

- `score.py` を書き終えたのは 2026-11-23 19:29:34 (JST)。全官署の取得は 19:31:12 に始まり 19:35:19 に終わった。評価の直前に `score.py` のハッシュが変わっていないことを確かめた。
- ただし、スコアを書く前の 19:26 に、表の様式を確かめるため宮崎の表を 1 件取っている。このときは値を伏せて、行と欄の構造と凡例だけを見た。
- 赤線の様式 (どのクラスが実線か) を読み違えていたことに、取得の前にスタイルシートを読んで気づき、`jma.py` を直した。スコアには触れていない。

## 出典とライセンス

- Alexandersson, H. (1986) A homogeneity test applied to precipitation data. J. Climatol. 6, 661-675.
- Khaliq, M. N. and Ouarda, T. B. M. J. (2007) On the critical values of the standard normal homogeneity test (SNHT). Int. J. Climatol. 27, 681-687.
- Peterson, T. C. and Easterling, D. R. (1994) Creation of homogeneous composite climatological reference series. Int. J. Climatol. 14, 671-679.
- 大野浩史ほか (2011) 気温の時系列データから気象官署の移転にともなう影響を補正する手法について. 測候時報 78, 31-41.

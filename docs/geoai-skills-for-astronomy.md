# GeoAI-master-skills の手法は天文学にどこまで使えるか

[GeoAI-master-skills](https://github.com/yuiseki/GeoAI-master-skills) は、地理空間データの分析を、データ選びから評価を疑うところまで進めるための手順書の集まりである。その手法を、公開アーカイブを再解析する天文学にどこまで持ち込めるかを検討した。

検討日は 2026-11-23。読んだ版は 692d2ea。

## 読んだ範囲

- 本文まで読んだのは experiment-design、observation-bias-audit、anomaly-detection の3つと、分析の流れを書いた AGENTS.md の冒頭である
- ほかのスキルは、名前と説明文だけで判断した
- 天文学の側は、このリポジトリの PoC (ZTF のアラートを Fink の API で扱う) で実際に起きたことと、Claudestronomy が掲げる6項目を基準にした。光度曲線の再解析に寄った見方であり、画像の重ね合わせや分光は検討していない

## 結論

スキルは3つに分かれる。

- 対象が地理でなくても成り立つ、推論の作法を扱うもの。ほぼそのまま使える
- 「空間」を「天球」や「時間」に読み替えれば使えるもの。読み替えの中身を書く必要がある
- 地表の構造 (道路、行政区、地形) を前提にしたもの。使えない

1つ目が最も価値が高い。天文学の再解析で詰まるのは、検出の技法より、見つけたものを信じてよいかの判断だからである。Claudestronomy の6項目も、6つとも判断の作法であって技法ではない。

## そのまま使えるもの

| スキル | 天文学での使い道 | この PoC での状態 |
|---|---|---|
| experiment-design | 主張、比べる相手、判断の規則、悪い結果の意味を、決め手の結果を見る前に書く。確認と探索を分ける。救済に使わない変更を名指しする | スコアは先に固定したが、判断の規則を書いていなかった。背景を採点する前に EXPERIMENT_PLAN.md を書いた |
| observation-bias-audit | 知りたい現象、発生の機会、記録の過程の3つを分ける。天文学では、天体の実在、観測されうる領域と期間、観測頻度と限界等級にあたる | n_det と duration は観測の努力を測っている。計画の「別の説明」に入れた |
| leakage-audit | 答えの言い換えと、予測する時点より後の情報を探す | Fink の d:tns に論文の後の分類が入っていた。スコアに使っていない |
| anomaly-detection | 比べる相手を先に決める。得点の上位は候補であって結論ではない。偶然で超える数を並べて書く。誤りか出来事かを別の資料で分ける | まだ使っていない。新しい候補を出す段階で要る |
| data-variable-semantics | 列が問いの言葉と同じものを指しているかを一次資料で確かめる | magpsf は差分画像の等級で、isdiffpos が偽なら暗くなった量である。PS1 の列は一致なしを -999 で表す。どちらも特徴量のテストに入れた |
| eda-and-baseline | どのモデルも超えるべき基準を、本番と同じ評価で出す | 基準が無い。「アラートの数だけで並べる」のような単純な順位と比べていない |
| robustness-analysis | 設定、標本、データの版を変えて結論が保たれるかを試す | 流していない。変える候補は FLARE_GAP_DAYS、週の取り直し、アラート測光と強制測光 |
| noise-ceiling-analysis | 目的変数の雑音から、超えられない点数の上限を見積もる | TNS の分類そのものが揺れる。正解表にも判別不能が2件ある |
| uncertainty-estimation | 確率の較正と、区間の被覆率をグループごとに見る | 分類器の確率を使う段階で要る |
| analysis-reporting | 結論の数字が出力ファイルにあるかを機械で確かめる | 使っていない。check_project.py はそのまま流用できる見込みだが、試していない |

### 特に効くもの: 記録の過程を分ける

observation-bias-audit の「記録が多い場所は、現象が多い場所とは限らない」は、天文学では選択関数の話そのものである。

| 地理での言葉 | 天文学での対応 |
|---|---|
| 知りたい現象 | 実在する天体や出来事 |
| 発生の機会 | 見えている体積、銀河の数、観測された期間 |
| 記録の過程 | 視野ごとの観測頻度、限界等級、太陽の裏に入る季節、銀河面を避ける方針、アラートを出すしきい値 |
| 努力をそろえて比べる | 同じ視野、同じ観測頻度の層の中で比べる |
| 独立した2つの記録の重なり (Chapman) | 2つのサーベイや2つのブローカーが拾った天体の重なりから、取りこぼしの下限を見積もる |

最後の行は、Claudestronomy が求める「感度と範囲を添えた null」を、注入試験なしで概算する手段になる。ただし2つの記録が同じ偏りを持てば、見積もりは下限にしかならない。これはスキルにも書かれている。

### 特に効くもの: 標本の重み

spatial-sampling-design は、包含確率と設計の重みを残せと言う。この PoC の背景は層ごとに同数を引いたので、全体の Inspection Load を言うには、層ごとの実際の件数で重みを付け直す必要がある。Fink の統計の API が夜ごとの分類別の件数を返すので、重みは作れる。今回は作っていない。

もう1つ、背景は「ある週にアラートが出た天体」から引いたので、アラートの多い天体ほど選ばれやすい。包含確率が天体ごとに違う標本である。

## 読み替えれば使えるもの

| スキル | 読み替え | 残る違い |
|---|---|---|
| cross-validation-design | 空間のブロックを、視野、CCD、季節、赤緯の帯に替える。同じ天体のアラートを学習と試験に分けない | 依存の構造が、近さではなく装置と観測計画から来る |
| spatial-autocorrelation、point-pattern-analysis | 候補が天球上で固まっていないかを調べる。基準の分布は一様ではなく、サーベイの観測範囲と深さにする | 固まりは現象ではなく、明るい星の写り込みや CCD の端であることが多い。平面ではなく球面で、H3 にあたるのは HEALPix |
| spatial-data-integration | カタログどうしの位置の突き合わせ。結合の前後で行を数え、落ちた行と重複した行を報告する | 突き合わせの半径が測位の誤差と固有運動に依存する。1対多が普通に起きる |
| dataset-discovery | アーカイブの列、粒度、時間の範囲、注意点を実測して書く | 版 (データリリース) の違いが大きい。アラートと強制測光は別のデータである |
| time-series-forecasting、spatiotemporal-modeling | 予測の時点より後を使わない採点は、そのまま光度曲線の早期分類に使える | 光度曲線は間隔が不規則で、誤差が点ごとに違い、複数のバンドがあり、上限値を含む。等間隔の系列を前提にした手順は使えない |
| sar-change-detection、image-segmentation | 出来事の前後を比べて記録と突き合わせる枠組みは、差分画像と同じである | 道具も誤差の性質も別物で、手順は持ち込めない。枠組みだけが共通する |
| clustering-analysis、dimensionality-reduction | 群や軸が設定を変えても戻ってくるかの確かめは、光度曲線の教師なし分類にそのまま要る | なし |

## 使えないもの

areal-interpolation、land-cover-cost、raster-cost-distance、spatial-network-analysis、spatial-accessibility-analysis、spatial-optimization、terrain-hydrology、poi-insights、travel-time-reliability、trajectory-prediction、spatial-gnn、street-imagery-inspection、location-privacy、grid-risk-mapping。

行政区、道路網、地形、施設、人の移動を前提にしている。grid-risk-mapping の「前の期間だけから履歴を作る」という部分だけは、時間のリークの防ぎ方として共通する。

## GeoAI-master-skills に無く、天文学で要るもの

- 注入と回収の試験。合成した天体を実データに入れ、探索の条件ごとに回収率を測る。experiment-design の「答えの分かる模擬」が最も近いが、手順は無い
- 完全性の曲線。等級、継続時間、観測頻度の関数として、どこまで見えていたかを示す
- 測光の扱い。差分画像、強制測光、上限値、赤方偏移による補正
- 追観測という評価器。候補の最終的な確認は別の望遠鏡でしかできず、その時間を申請する手続きがある
- 命名と報告の作法。候補を TNS などへ報告する決まりと、既に報告されているかの照合

注入と回収は、Claudestronomy の6項目の2つ目にあたり、この PoC に欠けている最大のものである。

## この PoC への反映

- 済み: 判断の規則を EXPERIMENT_PLAN.md に書いた。観測の努力、循環、標本の偏り、リークを「別の説明」として並べた
- していない: 基準の順位との比較、頑健性の確かめ、層の重み付け、注入と回収

していないものは、最初の表が出た後に、表の読み方を変えるものから順に足す。

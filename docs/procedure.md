# 手順: 広く調べ、重複を確かめ、検証できる問いを選び、実データで試す

分野を問わず使える形で、このリポジトリで実際に踏んだ手順を書く。天文学の PoC ([poc/ztf-rediscovery/](../poc/ztf-rediscovery/)) がその1回目である。

全体は5段で、どの段も次の段へ渡すものが決まっている。

| 段 | すること | 次へ渡すもの |
|----|----------|--------------|
| 1 | 候補を広く並べる | 候補の一覧 |
| 2 | 候補ごとに既存研究、公開データ、評価器を調べる | 候補ごとの現状の表 |
| 3 | 検証できる問いを1つ選ぶ | 問い、正解表の出どころ、対照の引き方 |
| 4 | 判定の手順を、正解表のデータを見る前に固定する | コミットされたスコアとテスト |
| 5 | 実データで試す | Recall と Inspection Load の表、分かったことと分からないこと |

## 1. 候補を広く並べる

深さより幅を優先し、空白の種類が違う候補を混ぜる。

- 未解析のデータ: 観測は済んでいて、再解析するだけで見つかるかもしれない
- 未実施の実験: 組み合わせが多すぎて人手では試しきれない
- 未接続の知識: 複数の分野にあるのに、横断されていない

この段では「注目度が低い」は推定でよい。実測は次の段でする。

## 2. 候補ごとに現状を調べる

1候補につき1回の検索を、並列で投げる。検索語には、対象のデータ名、手法の総称、今年の年を入れる。年を入れないと数年前の「これから」が上位に来る。

候補ごとに次の3つを表に書く。

- 既にあるもの: 同じ問いを大規模に解いた研究、専用の基盤モデル、事業者
- 公開データ: 認証なしで取れるか、どのくらいの大きさか
- 独立した評価器: AI の出した答えを、AI 自身とは別の方法で確かめる手段

混み具合は、検索の上位に同じ問いを解いた研究が出るかどうかで判断する。論文数は数えない。根拠が表題と抜粋だけであることは、表の前に書く。本文まで読んだものは、どれを読んだかを書く。

出版社のサイトは自動取得を拒むことがある。プレプリントのサーバーに同じ論文があれば、そこから読む。

## 3. 検証できる問いを1つ選ぶ

2 の表から読み取れたこと。

- 評価器が強い候補ほど混んでいる。検証が機械的にできると参入が進む
- 空きは分野の単位ではなく、既存の手順が対象から外した部分集合の単位で残る
- 問いそのものが最近の論文で回収されている候補は外す
- 障壁が言語やデジタル化にあると当の分野が書いている候補は、空きの信号が強い

問いは「新しいものを見つける」ではなく「既に見つかっているものを、どれだけの手間で拾い直せるか」に置く。再現できない手順が出した発見は、偽陽性と区別がつかない。

この形の問いには正解表が要る。見落とし事例を一覧にした論文、後から確定した分類、時点で分けた記録などが使える。正解表のライセンスと、正解表がどうやって選ばれたかを先に読む。選ばれ方が、後で測る数字の意味を決める。

## 4. 判定の手順を先に固定する

スコアやしきい値は、その分野の先行研究の基準から書き起こし、正解表のデータを取得する前にコミットする。正解表を見てから直すと、測っているのは手順ではなく調整になる。

特徴量の計算は、合成データのテストを先に書く。実データは欠測と外れ値だらけなので、何が正しい値かを実データでは確かめられない。

## 5. 実データで試す

小さく積む。

1. API や配布元から1件だけ取る。返る形、大きさ、時間を見る
2. 正解表の全件を取る
3. 対照 (背景) を引く。人が正解表を探すときに目を通すことになる母集団から、乱数の種を固定して引く
4. 正解表と対照に同じスコアをかけ、しきい値ごとに Recall (正解表の残る割合) と Inspection Load (対照が通る割合) を並べる

この段で特徴量やモデルを足さない。最初の表が出てから、足す理由があるかを判断する。

実データを読む実行は、メモリと CPU に上限を掛ける。長い取得は裏で流し、ログは作業ツリーの外に置く。

### 1回目でつまずいた点

- 列の指定で 500 が返る。Fink の API は派生列 (`v:`) を `columns` に入れると落ちる。エラーの本文は理由を言わないので、列を減らして切り分けた
- 「0件」が複数の意味を持つ。観測の無い週も、途中で使われなくなった分類名も、同じ空の配列で返る。分類ごとに 0 件の週を並べると、2 つを区別できる
- 層別標本は実際の混合比ではない。分類ごとに同数を引いたが、実際のアラートは「Unknown」が 1 夜に 10 万件、超新星候補は 1,000 件ほどである。全体の数字ではなく層ごとの数字を読む
- 正解表が後から答えを持つ。論文の後に分類が登録された天体があり、その欄を特徴量に使うと答えが漏れる
- 手元のデータと論文のデータが違う。論文は強制測光を使い、PoC はアラート測光を使った。アラートが 5 件しか無い天体があり、これは手順の弱さではなくデータの差である
